# 零点 App

React Native 与 Expo。一个 App 提供顾客、商家和平台管理身份，使用 LingDian API、现有业务规则及门店授权。

## 本地运行

在仓库根目录运行 `pnpm install --frozen-lockfile`，保持 [本地 API 的数据库配置](../AGENTS.md) 指向 `lingdian_cf_preview`。API 就绪后运行 `pnpm dev:mobile`。

- iOS 模拟器默认连接 `http://127.0.0.1:9000/api`，Android 模拟器默认连接 `http://10.0.2.2:9000/api`。
- 真机或其他测试环境可在 `mobile/.env.local` 设定 `EXPO_PUBLIC_API_URL`。真机需要能访问该地址。发布版使用 HTTPS。
- iOS 原生构建需要完整 Xcode、CocoaPods 和 iOS 模拟器运行时。Android 原生构建需要 JDK 17、Android SDK 36 和 NDK 27.1.12297006。
- `pnpm --filter @lingdian/mobile ios` 和 `pnpm --filter @lingdian/mobile android` 会生成并运行各平台开发构建。Web 预览用 `pnpm dev:mobile --web`，其浏览器来源须在 API 的 CORS 配置中。
- `pnpm build:mobile` 导出 iOS、Android 和 Web 的 JavaScript 与资源。`pnpm --filter @lingdian/mobile test` 运行模块测试。

## 身份与联调

登录时选择短信验证码或账号密码。顾客短信登录需确认 App 专用协议及隐私政策。账号密码验证后自动进入唯一获授权的身份，有多个可用身份时先选择。平台管理也支持后端授权的管理员短信登录。已登录用户通过顶部身份入口切换到同一账号获授权的身份，首次进入一个新身份需要验证该身份的凭证。商家通过门店入口切换服务器返回的授权门店。

- 顾客可以浏览菜单、选择规格、提交订单、新增或编辑收货地址及管理个人资料，付款使用现有线下收款规则。配送结算会核对地址版本，地址发生变更时需重新选择。
- 结算会核对当前菜单、规格与应付金额。顾客可在结算时重新选择失效条目的规格或选项，保留数量。订单金额在提交时发生变化，顾客需核对新金额后再提交。
- 多门店部署支持搜索和选择顾客门店，菜单显示所选门店的商品、营业状态和服务方式。
- 原生 App 按门店、账号与访客加密保存购物袋。登录时，可完整合并的访客商品会转入顾客账号。Web 预览在当前浏览器标签页保留购物袋。
- iOS 和 Android 会加密保存待确认的订单。网络中断后可在同一账号下继续确认，App 会沿用原门店和请求编号。Web 预览会在当前页面运行期间保留待确认订单。
- 商家可以在选定门店经营订单、商品、配方、原料、库存、盘点、采购与集成，报表支持导出 CSV。
- 商家可以从补货建议查看对应原料的在途采购，或带入建议数量创建采购单。收货报表支持按供应商和原料汇总，并查看对应明细及采购单。
- 商品详情支持单独调整规格售价和参考库存。可售数量按原料库存和规格配方核算。
- 平台管理可以查询订单、维护账号与门店授权。系统日志与收款账户编辑依然由超级管理员权限控制。
- 平台可以为只有手机号的顾客设置临时登录凭证与商家门店授权，顾客使用同一个账号切换身份。
- 商家和平台管理可以按来源筛选订单，平台还可以按门店筛选。订单汇总沿用列表条件。商家经营明细支持按订单状态或服务方式查看对应日期内的订单，并导出经营快照。
- 商家可从订单列表查看取餐码，直接确认线下收款、开始制作、备餐完成及交付。订单发生变更时，刷新后需重新确认。
- 站内信覆盖顾客订单进度、商家新订单与库存预警、平台新订单和超级管理员严重系统告警。消息按身份、账号与门店记录已读，展示最近 30 天。App 前台刷新未读状态和提醒。
- 进入子页面时保留上一页的输入与筛选，暂停上一页的数据查询。返回时按缓存状态刷新。

联调环境需运行支持 App 协议版本并包含 `auth/mobile`、`mobile/orders` 与 `mobile/inbox` 路由的 API。按项目的迁移发布流程应用 `20261125_z_mobile_inbox` 和 `20261125_zz_mobile_order_source`。App 订单带有独立渠道标识和 `APP-` 开头的取餐码。
