# LingDian 模块目录与实现状态

> 审查基线：2026-08-30 当前工作区。本文是代码事实目录，不是产品承诺。系统关系见 [系统结构](./11-system-structure.md)，风险优先级见 [权限与缺口分析](./13-permission-and-gap-analysis.md)，本轮修复见 [代码库全面审查](./14-codebase-review-2026-08-30.md)。

## 1. 状态口径

| 状态 | 定义 | 对外口径 |
| --- | --- | --- |
| **已实现** | 主流程、权限边界、异常处理和基本测试均存在 | 仍须目标环境验收后宣称可用 |
| **部分实现** | 有真实 API/数据链路，但关键分支、运营处置或产品入口未闭环 | 只能说明已完成子能力 |
| **占位** | 页面、字段或壳存在，数据仍是静态值或说明 | 不得宣称可用 |
| **缺失** | 仓库中没有可执行主流程 | 不得宣称可用 |

判断模块成熟度同时检查：入口、服务端规则、数据范围、持久化、并发/补偿、审计、测试和运营处置，不能只看页面或数据表。

### 4.1 订单和支付不变量

- 顾客订单、支付查询和幂等重试都先做 owner + 主门店 scope；
- 下单金额由服务端从 SKU 和选项重算，客户端金额不作为事实；
- 同一门店、顾客、请求 ID 的订单唯一；同一订单只允许一个活动支付尝试；
- 订单终止和支付预占锁定同一订单行：终止先提交则支付条件更新失败，支付已预占则终止回滚拒绝；
- Connector 同步终态不作为资金事实；成功、重复和迟到 webhook 走统一确认事务；
- 失败意图不会被迟到 `PROCESSING` 复活，迟到成功标记 `LATE_PAYMENT`；
- 本地过期不直接释放活动意图；只有 Connector 按 `payment_no` 返回持久 `CLOSED` 凭证后，才在 order → intent 锁顺序下标记 `EXPIRED` 并允许新尝试；
- 非现金订单不能通过通用订单状态接口手工确认支付或退款。

## 6. 模块维护要求

每次改变模块状态时，至少同步：

1. API/事件契约与数据库所有权；
2. audience、角色、owner/store scope 和敏感动作权限；
3. 幂等、并发、失败补偿和人工运营入口；
4. 客户端真实入口、空态和 feature flag；
5. 单元/集成/迁移测试及 600 行、循环依赖、文档链接门禁；
6. 本文状态、[系统结构](./11-system-structure.md) 中的边界和 [权限与缺口分析](./13-permission-and-gap-analysis.md) 中的上线条件。
