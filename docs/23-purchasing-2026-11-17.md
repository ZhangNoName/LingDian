# 采购与补货闭环 · 2026-11-17

## 产品流程

库存页新增“采购与补货”，包含采购单和供应商两个视图。流程为创建已有原料的采购单、按实际验收数量分批收货、全部收齐，或取消未收部分。桌面列表和手机卡片保留单号、供应商、状态、采购/实收金额、创建时间和详情入口；手机折叠筛选，导航单行滚动，避免挤满首屏。页面、表单、状态和错误共用简体中文/英文设置，业务名称和备注保留原文。

- 供应商按门店建档，维护编码、名称、联系人/联系方式、说明和启用状态。编辑校验版本，编码在店内唯一；停用只阻止新采购，不阻止已有单收货。采购单固定供应商名称/编码快照，供应商改名不改写旧单。
- 创建单选择当前门店已启用供应商和已有原料，最多 50 种。查找每次最多 20 个结果，可按编码/名称缩小范围；同原料不能重复添加。默认采购数量参考当前阈值缺口，用户确认数量和单价。保存后供应商、明细、数量和单价不可编辑，变更时取消剩余并新建。
- 每行数量最多三位小数，单位固定；单价 CNY 至多两位小数。收货可只填写部分原料，不能超过各行剩余数量；说明必填。页面明确保存会增加库存并更新预警，不能在此撤销。
- 取消前展示影响并要求原因。只取消剩余，不冲回已收库存、金额或历史；取消后禁止继续收货。重试同一取消操作可安全返回既有结果。
- 收货记录保留经办人、时间、备注、数量和按分舍入的行金额，独立分页；不会默默截断全部历史。库存流水关联采购单，可直接打开详情。
- 列表可筛选待收货、各状态和关键词，导出当前页 CSV，清楚携带门店、筛选与分页上下文。库存区间报表自动包含采购 RECEIVE 流水，不另建重复库存来源。

采购不会自动发送给供应商。本轮是采购记录和入库流程，尚无采购审批、退货、作废收货、供应商付款、发票/税费、单位换算或库存成本估值。已有原料手工入库入口仍保留，真实业务应避免对同一到货同时登记手工和采购入库。

## 一致性和多租户

新增 Supplier、PurchaseOrder、PurchaseOrderLine、PurchaseReceipt、PurchaseReceiptLine，以及库存流水到收货单的关联。供应商、采购单、原料和收货明细使用包含 storeId 的复合外键；所有读写先检查当前商家签名会话的门店范围。

采购单创建和收货使用店内唯一 requestId 与规范化请求 SHA-256（包括当前用户、对象、数量、版本等）保护重放。同请求重试返回已经提交的记录，不同内容复用请求键拒绝。UI 在同一表单生命周期中保留请求键，失败保留输入；响应不确定时重试原内容不会重复入库。关闭/重新创建表单会开始新请求，操作人员应先刷新核对现有记录。

创建单先锁供应商，防止与停用并发。收货先认领采购单版本，然后读取最新明细，按原料 ID 顺序加锁，基于当前数量、预占量和可用量入库。采购行累计收货、采购状态/金额、原料数量、库存流水、预警解除和业务审计在一个 ReadCommitted 事务提交或回滚。已预占量不变，可用量增加；超库存上限、超收、越权引用和冲突都会失败，不部分入库。库存调整、订单预占及采购收货遵循一致的原料锁顺序。

库存数量保存为千分整数，单价为整数分，行金额用 BigInt 乘除后按半入舍入到分，检查安全整数后才返回 JSON。每次收货按该批各行独立舍入，累计实收金额不强制等于整单计划金额；细分收货产生的舍入差异属于当前记录口径。采购单不代表付款或库存估值。
