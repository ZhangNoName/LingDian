# 原料库存台账迭代与 Review · 2026-11-17

## 目标与交付

将仓储占位页替换成商家可操作的原料库存台账。默认生产导航开放“库存管理”，其余未完成的会员、营销、经营分析、财务模块继续受 feature flag 保护。

工作流参考 [Shopify 库存管理](https://help.shopify.com/en/manual/inventory-and-locations/adjusting-inventory) 中的筛选、调整和历史追溯模式；本产品采用原料建档 → 入库 → 出库/盘点 → 预警 → 查流水/导出的一条路径。

已完成：

- 原料编码、名称、固定单位和预警阈值建档，初始库存为零；门店内编码唯一。
- 入库、出库、盘点、阈值设置。表单展示调整前后数量，强制填写原因。
- 缺货/低库存计数、名称/编码搜索、状态筛选、分页和按原料查询历史。
- 记录时间、操作人 ID、原因、数量和阈值变更前后值，不开放修改/删除流水。
- 库存和流水当前页 CSV，包含门店、筛选/原料条件、导出时间与页码，防公式注入。
- 库存页、编辑窗口及导航框架的简体中文/英文切换；持久化语言偏好，数量和时间按语言格式化。业务原料名称/单位不自动翻译；旧业务页面正文尚未全面国际化。
- 移动端工具栏换行、表格局部横向滚动，弹窗限制高度并支持滚动。

## 服务端不变量与 Review

- 每个库存接口使用 `AccessTokenGuard + MerchantGuard`；服务层先做 `MerchantStoreScope`，再查对象/幂等结果。
- `InventoryItem`、`InventoryMovement` 均保存门店 ID，复合外键限制流水引用同店原料。沿用现有生产单店 resolver，保留租户边界；本轮没有启用跨店经营。
- 数量保存为整数千分量，单项最多 999,999 个单位，非负、最多三位小数。固定单位防止历史含义改变。
- 调整使用 `expectedVersion` 比较更新，成功后版本递增；更新和流水写入在同一数据库事务。并发旧版本拒绝，不静默覆盖。
- 门店内 `requestId` 唯一；重试必须匹配原料、操作人、方式、数量、原因和原版本，返回原流水。
- 零库存属于缺货；正库存小于等于阈值属于低库存。补至阈值数量为 `max(阈值−库存, 0)`，等于阈值时显示低库存但差额为零。
- 总览计数覆盖整个门店，列表筛选仅影响列表；界面标明计数口径。读取失败不展示旧表格或允许导出旧数据。
- 浏览器检查发现并修复：移动端 Grid 被表格撑宽、首页导航在子页面仍高亮。

## API 与迁移

以 `/api/merchant/stores/:storeId/inventory` 为前缀：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/` | 库存分页、筛选与门店计数 |
| POST | `/` | 新增原料 |
| GET | `/movements` | 流水分页，可选 itemId |
| POST | `/:itemId/movements` | 入库、出库、盘点或阈值调整 |

新增迁移 `20261117_inventory_ledger`，只新增原料和流水表，不回填/推断现有 SKU 库存。部署时先备份并通过现有安全迁移入口 `pnpm run db:migrate:deploy`，再启动新 API。不要对生产运行 db:push。

## 验证边界

- 库存服务/DTO 测试覆盖门店越权、对象越权、整数精度、重复请求、请求冲突、并发版本、缺货、归零盘点、阈值审计、溢出和请求验证。
- Web 测试覆盖 CSV 编码、引号/换行转义、公式注入和语言字典完整性；导航测试随真实模块开放更新。
- 浏览器验收使用拦截 API 的本地测试数据，不代表真实数据库或生产联调。覆盖列表、低库存筛选、入库、流水、CSV 下载、英文、新增原料、390px 移动布局及加载失败。
- `pnpm test`：610 项通过，1 项因本机无 Docker Compose v2 跳过；`pnpm run type-check`、`pnpm run build`、Prisma schema validate 和 `git diff --check` 通过。最后的 UI 微调后再跑 Web 测试（75 项通过）及 Web 构建；构建仍有上游工具链的非阻断警告。
- 当前环境没有可用的隔离 MySQL/MariaDB 实例，本轮没有执行真实数据库迁移及数据库级并发/回滚验收。发布前必须在隔离数据库跑完整迁移和并发场景，不能将单元测试视为数据库验收。

## 后续计划

1. 在隔离 MySQL 8.4 上执行空库迁移、drift、同原料并发调整、同请求并发重试及流水失败回滚验收。
2. 原料归档、历史查询的日期/操作类型筛选、按区间汇总的出入库/损耗报表及全量异步导出。
3. SKU 库存预占、确认扣减、取消/超时释放，以及商品配方与原料消耗。需与支付、订单状态统一事务和幂等口径。
4. 采购/供应商、员工动作权限、统一审计、通知偏好与可重试预警发送。
5. 单独设计多租户运行时、成员关系与跨店政策；扩展其他模块的多语言正文。当前持久化/接口租户边界继续保留。

原料台账不承担订单可售承诺，不自动扣料；无库存金额估值、采购单、供应商、跨店调拨和邮件/短信推送。经营分析占位页仍未作为真实报表开放。
