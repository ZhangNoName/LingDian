# 预警定位与跟进复核 · 2026-11-18

## 交付流程

预警中心将已应用的处理状态、级别、原料名称/编码及页码保存到 URL。筛选修改后统一点击“查询”应用；未应用时提示并禁用刷新、分页和导出，避免导出条件与眼前输入不一致。重置筛选回到处理中第一页，清除所选详情。预警处理后不再符合筛选或末页变空时，列表自动收敛到有效页。

查看预警使用精确 ID 读取最新详情，不再把列表快照作为确认依据。详情 ID 与列表筛选独立：刷新带详情的链接、浏览器前进/后退均可恢复详情，即使该记录已移出当前页或状态筛选。关闭详情保留筛选/页码并刷新列表；若记录数已减少，页码按实际结果收敛。前往库存或补货继续复用当前选店与既有入口，浏览器后退可重新读取来源预警。

状态冲突保留输入的跟进安排，禁用继续确认，并提供“重新读取”。读取后明确提示核对状态和数量，再由用户决定是否确认；不自动提交保留的草稿。若预警已被他人跟进或已解除，未提交安排以只读文本保留供复制，不写入已结束的记录。普通网络失败仍可按相同身份、版本和备注重试；服务端原有确认重试规则不变。

确认成功后留在详情，显示最新跟进状态、操作人及备注，同时刷新列表/顶栏计数。保存期间禁用关闭按钮、Esc 与外部点击；读取失败隐藏旧详情及库存/补货/确认动作，重新读取成功后才恢复。详情内重新读取不会改变库存或解除预警。

## 布局与导出

桌面保留表格和直接可用的筛选栏；手机使用卡片、折叠筛选和条件摘要，将预警及导出说明折叠，优先露出记录。中英文同步维护，名称、编码和备注仍为业务原文。全店当前预警计数明确标注不受列表筛选影响。

CSV 明确为当前筛选的本页记录，新增预警编号和原料编号，便于区分同一原料的多次预警；保留门店、筛选、导出时间、页码、发现/最新数量、跟进人/备注、解除原因等信息，沿用公式注入防护。跨页结果会随业务变化，不代表全量冻结快照。

## API 与门店边界

新增 `GET /api/merchant/stores/:storeId/inventory/alerts/:alertId`，沿用 AccessTokenGuard 与 MerchantGuard，服务层先验证签名门店范围，再按 `id + storeId` 复合键查找；跨店对象返回不存在，未授权门店先拒绝。预警与原料关系元信息在 RepeatableRead 事务内读取。接口不写预警、原料、版本、更新时间或审计；无需迁移。

URL 只保存查看状态，不授予权限，也不自动切换门店；接收链接者须在已授权的对应门店查看。切店清除详情 ID，失效/重复/超长 ID 不用于打开记录；查询与详情均防止卸载后的延迟响应回填。筛选字段仅在各自命名空间归一化，不删除其他库存工作区查询字段。关闭整个窗口、刷新或离开页面不会保存未提交的跟进文本；文本不写 URL 或浏览器存储。

本轮沿用商家门店权限，不新增审批、员工动作权限、外部通知或手工解除预警能力。自动升级、恢复/停用解除和确认跟进的版本/锁顺序/审计规则保持有效。
