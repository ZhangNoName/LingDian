# 销售配方、订单原料库存与 Review · 2026-11-17

## 经营流程

在已有门店台账、预警、变动记录和区间报表上，补齐“配置销售配方 → 下单预占 → 收款扣料 → 取消/到期释放”。当前租户边界仍是门店；没有新增跨店库存、采购或组织层级。

- 库存页增加“销售配方”，搜索商品/规格，为每份规格添加原料与用量；原料可按名称/编码搜索，每个配方最多 20 项。
- 列表显示在库、已预占、可用库存，预警和补货差额按可用量计算。手工出库、损耗、盘点不得占用已预留给订单的原料。
- 配方与弹窗提供简体中文/英文，手机上纵向排列输入；保持现有表格、列表和轻量表单，不新增装饰图表。
- 配方清空只影响后续订单；已经下单的订单使用不可变原料预占快照。顾客订单详情在待付款时显示原料预留截止时间，缺货时显示可理解的提示。

## 数量与事务

原料固定单位的千分量是事实来源，旧商品/SKU stock 字段仍是维护字段，不同时重复扣减。未配置配方的规格延续原有不限量/人工售罄方式；基础规格与所选 VARIANT 引用规格的配方追加计算，业务人员应避免重复配置。

`在库 = 已预占 + 可用`

- 下单同事务校验当前门店和有效 SKU、锁定配方、按原料合并需求，检查可用量并创建 RESERVED 快照、RESERVE 流水和 30 分钟截止时间。原料不足则订单及库存全部回滚。
- 现金确认/验签支付成功在调用方订单事务中 COMMIT：在库与预占同时减少，可用不变，快照转 COMMITTED，写 ISSUE 流水。
- 取消、失败或超时在同事务 RELEASE：在库不变，预占减少，可用恢复，快照转 RELEASED，写 RELEASE 流水。
- 锁顺序为订单 → 排序 SKU → 排序原料；下单、配方替换、订单状态与支付事务使用 ReadCommitted，在等待锁后读取最新配方/数量。版本更新与数据库余额 CHECK 共同保护数量不变量。
- 重复订单沿用既有幂等键；重复确认/终止由状态条件更新、预占状态与唯一流水请求键收敛。配方写入 auth audit，库存流水保留 actor、订单号、物理量和预占量前后值。
- 退款不自动补回原料，避免把已经制作/消费的原料虚增；实际退料需要人工登记与原因。

到期 worker 启动时及每 15 秒扫描 20 单，按截止时间/id 游标轮转，避免最早一批支付不明订单阻塞后续订单。先调用支付恢复/关单，再事务终止订单；活动或结果不明的支付仍阻止释放。多实例竞争由既有订单条件更新和事务保护，进程内防重入。当前只处理有原料预占的订单，不是完整支付对账或全部订单超时产品。

区间报表继续计算物理量：RESERVE/RELEASE 不进入出入库数量，但计入记录数。ISSUE 仅在确认收款时影响收支；配方预占不会把报表期末伪装成可用量。

## 迁移审查

新增 `20261117_order_inventory_reservations`：可用量从现有物理量回填；新增非负余额 CHECK、配方、预占快照、预占流水前后值、订单截止时间及复合门店外键。保留现有单/多店身份校验，不迁移推断业务配方。MySQL 自动创建的复合外键索引在 Prisma 模型中显式映射，避免 drift。

真实 MySQL 空库验证发现旧迁移 `20260830_session_and_payment_invariants` 的支付唯一索引名长达 65 字符，超过 MySQL 64 字符限制。已改用 Prisma 生成的 64 字符名称并明确 schema map；增加全部迁移索引/约束名称的长度回归检查。

这是历史迁移内容修正，部署前必须检查目标库迁移记录与实际结构。若旧迁移已失败，MySQL DDL 可能部分生效，停止写入并核对已执行 SQL，选择经过验证的备份恢复或制定前向修复方案；不要盲目重跑、db:push、删除迁移记录或直接 resolve 为 applied。若迁移被人工标记完成或校验和不同，也需核对实际索引与完整 schema 后制定修复。仓库的迁移树回滚门禁会将此内容变更视为不兼容，不能期待自动回滚应用。此次未连接或修改真实业务数据库。
