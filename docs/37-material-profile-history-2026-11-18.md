# 原料名称与档案记录 · 2026-11-18

## 使用流程

原料详情新增“修改名称”，只允许对启用原料维护名称并填写原因。编码、单位仍固定，名称允许同店重复，原料身份以 ID/编码区分。更名不会调整账面、预占、可用量或阈值，也不会生成库存流水或重开预警。

表单显示当前名称，保留新名称和原因；相同名称不提交。保存期间禁用关闭、Esc、外部点击及重复提交。状态冲突禁用保存并提供“重新读取”，保留输入；读取成功后展示当前名称，再由用户确认保存，不自动提交草稿。读取失败继续保留输入并禁止保存；若原料已停用，表单只读，不以更名恢复原料。错误和提示随中英文切换。

当前表单在响应不明时可以保持内容不变重试。服务端仅在该更名的结果版本仍为当前版本、操作人/原因/前版本/目标名称全部一致时返回原结果，不重复新增记录；发生其他写入后，旧请求仍需重新核对。关闭或离开整个窗口不持久保存未提交文本，不把名称草稿或原因写入 URL/本地存储。

原料详情新增折叠的“档案记录”：按全部/更名/停用/恢复查看，包含前后名称或启停状态、操作人 ID、时间及原因，不提供修改/删除。每页 20 条；切类型回第一页，超出末页时收敛到实际末页。处理更名后保留打开的类型/页码并重新读取；整个详情关闭或页面刷新后，记录面板查看状态重置。

## 名称与历史口径

- 流水、区间收支、预警及配方等原料关系读取使用当前名称；数量、单位、原料 ID 和原始流水不会因更名改写。档案记录保留更名前后的名称供追查。
- 已保存采购/收货与盘点明细继续保留建单时的名称快照。更名不改写旧单据，也不改变原料关联。
- 更名与库存、阈值、启停共用原料版本和锁；过期调整/盘点不能借此绕过复核。即使数量未变，旧盘点草稿也可能需要重新取账面并核对实盘；界面提示同时覆盖资料与库存变化。
- 清单正按旧名称筛选时，更名后可能不再匹配；详情保持精确 ID，关闭后保留筛选并显示实际查询结果，不跳到相似名称的另一原料。

CSV 明确为所选类型的当前页，包含当前门店、原料 ID/编码/当前名称、读取时间、类型/页码/总数及本页变更前后值、操作人、时间与原因；使用既有公式注入防护。跨页查询可能变化，不将当前页导出称为全量或冻结历史。

## 服务与迁移

新增 `InventoryMaterialChange`，与原料使用 `itemId + storeId` 复合外键，按门店/原料/时间/ID 索引读取。新更名和启停操作在同一事务内写业务事实、档案记录与身份审计，任一记录失败整体回滚；不读取或暴露通用认证审计的 IP、设备、会话等元数据。原料“档案记录”只覆盖更名及启停，库存数量/阈值仍看既有台账，并非全系统审计中心。

库存前缀 `/api/merchant/stores/:storeId/inventory` 下新增：

| 方法与路径 | 请求/作用 |
| --- | --- |
| `PUT /items/:itemId/name` | `{ name, expectedVersion, reason }`；拒绝注入编码、单位、门店或数量 |
| `GET /items/:itemId/changes?kind=ALL&page=1` | ALL / NAME / ARCHIVE / RESTORE；固定每页 20 条，同一 RepeatableRead 快照读取当前原料与记录 |

两个接口均先执行签名商家门店范围，再按复合门店原料键查询。更名复用原料行锁，拒绝跨店对象、过期版本及停用原料；读取不改变原料版本、更新时间或记录。前端再核对详情身份，失败时不展示旧列表/导出，丢弃卸载/切店后的迟到响应。仍沿用商家权限，本轮不新增员工岗位、审批、成本估值或外部通知。

新增第 26 个迁移 `20261118_zzzzz_inventory_material_changes`。迁移只建新表/索引/FK，并从现有原料启停审计中复制可验证记录：事件、门店/原料、状态和原因必须匹配；保留原 ID、时刻、操作人及有效原版本，缺失/无效版本保留为空。错店/孤立关联、错误状态、非法原因和非原料事件不迁入；原审计和原料均不改写，不推断缺失操作或保证未记录的历史。

部署仍按现有流程备份、停 API、安全执行 `pnpm run db:migrate:deploy`，再发布新 API 与 Web；不使用 db:push。跨该迁移的旧应用回滚仍受现有迁移树兼容校验限制。
