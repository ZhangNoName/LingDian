# 商家语言入口、账号与集成设置 · 2026-11-17

## 使用流程

将商家业务页分散的语言控件合并到工作台头部；登录/重设密码页使用同一控件。简体中文/英文偏好在刷新、跳页和退出后保留，页面标题、浏览器标题及 HTML lang 同步。业务填写内容（门店名、昵称、商品等）保持原文。

商家登录、忘记密码、修改密码、昵称、门店信息和系统设置补齐中英文。账号页复用原生表单、密码显示/隐藏与简洁卡片，错误和成功提示使用可读状态；保存/发码期间防止重复操作并禁用相应输入。登录仍支持旧密码最小长度，新密码沿用服务端至少 12 字符的要求。

- 昵称先读取当前用户已有值，读取失败提供重试；修改仍只作用于当前用户，不因选择门店改变账号归属。
- 修改密码后清理当前前端会话并返回登录，重设密码请求保持通用提示，不透露账号是否存在。验证码错误/过期、频率限制、手机号缺失和网络异常提供本地化消息；未知服务端细节不直接显示。
- 登录完成提示使用受控 notice 枚举，不回显 URL 中任意 message。服务端退出未确认时，返回登录并说明本机状态已清除，不伪称服务端已经撤销。
- 将昵称/改密入口收进系统设置，移除每个业务页重复的账号链接；菜单说明与实际已实现能力一致，不再暗示已提供岗位/设备权限管理。
- 门店资料明确只读，显示当前门店、营业状态、编码和授权店数，提供商品/库存入口。营业配置编辑仍需平台管理，本轮没有添加虚假的保存按钮。

## 集成设置

改用带可读名称、状态和禁用反馈的原生 switch，去掉页面中 SDK、签名等实现细节。未接入的服务禁用，并给出联系管理员的原因；“可用”仅代表部署已配置并开放，不代表已经通过外部服务健康验证。

提供可选 reason_code（DEPLOYMENT_DISABLED / NOT_CONFIGURED），界面据此翻译，保留 reason 兼容已有调用方。启停请求在同一页面串行执行，避免多个开关并发覆盖 loading 状态；失败保留原有显示并提示刷新核对，不乐观假定保存成功。

当前门店切换使旧加载/写入响应失效；能力列表与单条保存响应必须匹配当前 store_id 和 provider，异常跨店/重复提供方结果直接拒绝展示。服务端仍先检查 merchant/store scope，不能靠隐藏按钮授权。开关更新与 INTEGRATION_SETTING_UPDATED（当前用户、session、门店、提供方、目标状态）在同一事务提交或回滚。

开关仍采用现有最终写入状态，没有新增跨用户乐观锁、投递历史/重放或员工动作权限。关闭不会撤销已投递记录；不保证已经入队的事件会被撤销。

## 账号和部署边界

新增受 AccessTokenGuard 保护的 GET /auth/profile/nickname，与既有昵称修改一样只使用认证用户 ID，返回昵称本身；顾客资料/头像接口的 UserApiGuard 保持不变。

登录设备标识在浏览器存储不可用时使用当前运行时的稳定内存值，避免本地存储异常让登录无法发起。access token 仍只保存在内存；没有把验证码、密码或刷新凭证写入 URL/本地存储。

没有新增数据库迁移。API/Web 同步发布后可获得昵称预填和 reason_code；昵称读取接口未更新时，界面明确失败并允许重试，不把空值当作读取成功。

- 隔离 MySQL 8.4.13 完整重放现有 19 个迁移，结构与历史无漂移。生产服务验证集成身份审计、审计失败回滚、越权门店/未配置提供方拒绝及昵称查询/修改；既有订单、库存、预警、采购与报表检查继续通过。
- 单元测试覆盖认证错误分类和未知细节隐藏、页面标题、外语状态、跨店/重复能力响应拒绝、设备存储失败、标准 Nest 错误解析、昵称最小读取范围及接口 guard。
- 浏览器使用合成 API 数据验证登录/重置/改密、通用找回提示、密码显示、一个语言入口、语言保留/即时翻译、昵称预填/重试、开关串行/失败/切店、错店响应拒绝、手机布局和退出未确认提示。此项不会真实发短信或调用外部连接器。

`pnpm test`：714 项通过，1 项因缺少 Docker Compose v2 跳过；全仓类型检查和构建通过。最后门店错误语言状态调整后，Web 类型检查、113 项测试和浏览器完整回归通过，覆盖首次强制改密与门店列表失败时即时切换语言。维护性、循环依赖、文档链接和差异检查通过；构建保留既有上游工具链非阻断警告。验收后停止临时 MySQL/Web，清理临时数据库运行目录。
