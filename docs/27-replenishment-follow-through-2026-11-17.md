# 预警到补货追查 · 2026-11-17

## 日常操作

预警详情和有短缺的库存行增加“查看补货”，按当前门店的原料 ID 定位，而非用名称或编码模糊匹配。指定原料默认显示全部补货状态；即使缺口已被未收采购覆盖，也能查看该原料及其未收采购，不会误显示“没有额外缺口”后丢失后续入口。

补货行增加“查看未收采购”，保留当前补货关键词、原料和状态，进入该原料尚未收齐的采购单列表。列表显示该原料的未收量/单位、预计到货时间和整单金额，可打开既有详情登记收货、取消剩余并查看收货记录，随后返回原补货筛选。口径说明可展开，桌面使用表格、手机使用卡片；沿用全局中英文。

- 指定原料与补货状态保存在 URL，刷新/分享保留对象范围；关键词与原料取交集。
- 未收采购列表沿用每页 20 行和“导出当前页”；CSV 附原料范围、单页信息、该原料未收量和预计到货时间，不声称是完整快照。采购金额仍是整单金额，不把它当成指定原料成本。
- 收货/取消后重新读取列表，已完成的原料行会移出追查结果。未收采购仍不增加现货或订单可用库存，也不自动解除预警。
- 切店清理采购详情、未收/补货原料以及报表供应商/原料等对象 ID，保留通用视图和时间条件；旧请求随页面销毁失效。外店对象不能扩大查询范围。
- 供应商、采购单创建、既有单据和库存流水继续使用现有服务，没有新增库表、迁移或新的 UI 依赖。

## 未收口径修正

此前补货汇总筛选 OPEN/PARTIAL 采购单的所有原料行。多原料采购单中，某种原料已收齐、其他原料尚未收齐时，该原料的未收量为零但仍被计入未收单数。

本轮以共享 `pendingPurchaseLines` 定义：原料行属于当前门店、订单也属于当前门店且状态为 OPEN/PARTIAL，并且 `receivedQuantity < quantity`。列间比较由 Prisma FieldRef 在数据库执行；汇总和追查列表共用这一定义，在 RepeatableRead 快照内分别读取页面与总数。已有每单每原料唯一约束确保原料行数对应未收采购单数。取消/收齐的订单及已收齐的原料行不再参与。

采购列表新增可选 `pendingItemId` 参数，仅应用于采购单列表 DTO；普通采购查询、供应商和收货记录接口维持原含义。参数验证长度与非空，先检查商家门店 scope，再执行门店限定查询；关键词和状态附加条件与未收原料范围取交集。
