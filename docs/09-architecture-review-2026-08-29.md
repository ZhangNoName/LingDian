## 保留风险与后续决策

- 库存字段已经存在但订单尚未形成“预占—支付确认—取消释放”的完整状态机。直接在下单时扣减会造成未支付订单占库，直接忽略又会超卖；应在明确库存策略后引入 reservation 表和超时释放任务。
- `products.service.ts` 接近千行，已经超过单一应用服务的合理边界。新增库存、套餐或渠道价前应拆分查询、命令、配置和图片能力。
- 收银与打印当前完成的是可靠 connector 协议，真实厂商指令需要在确定设备型号、通信方式和 SDK 后在 connector 项目实现。
- 美团/京东正式上线仍依赖主体资质、平台审核、官方文档/SDK 与测试账号；核心仓库不会用猜测字段模拟官方协议。
- 页面仍存在较多局部硬编码中性色。共享语义令牌已统一入口，后续页面改版应逐模块迁移并配合截图回归，不建议一次性机械替换造成视觉回归。
- 剩余依赖审计项来自旧版 uni-app 工具链中的 Vite/esbuild/phin，以及 Prisma CLI 的 `deepmerge-ts`。它们不位于 NestJS API 线上请求链路；升级需跟随 DCloud/Prisma 的兼容版本，当前不做高风险强制跨版本覆盖。
