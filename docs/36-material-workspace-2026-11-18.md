# 原料详情与清单工作区 · 2026-11-18

## 交付流程

库存清单中的原料名称成为详情入口。详情按当前门店和原料 ID 重新读取，集中展示账面、预占、可用库存、预警阈值、补至阈值、更新时间与启用状态。可用量明确按账面减预占计算，未收采购不算现货。停用原料继续可查详情、记录和关联信息，恢复前不提供调整或补货动作。

详情提供调整、补货、近 30 天记录/收支、关联业务和停用/恢复。桌面清单行保留“调整、记录”两个快捷动作，将较少使用的停用/恢复和补货放进详情，避免一行排列多个操作。手机清单改为卡片，分别展示账面/预占/可用量，筛选折叠并显示已应用条件；不新增一级菜单。

关联业务复用配方、采购和盘点详情，停用流程与原料详情共用同一业务窗口组件。一次只打开一个窗口，处理或取消子窗口后重新读取原料和关联记录，保留原料窗口中的关联分类/页码。原来的停用窗口仍保留停用原因及依赖复核流程。

库存调整沿用原版本及请求键。当前表单的相同内容在响应不明时可按原请求重试；过期版本拒绝写入并保留表单。保存期间禁用关闭按钮、Esc 和外部点击，完成事件先通知来源再关闭，详情重新读取最新状态。卸载/切店后的迟到结果不向新页面写成功/错误状态。读取失败隐藏旧详情动作，重读成功后再继续。

## 链接与记录/报表

清单筛选与页码使用独立字段：

| 字段 | 作用 |
| --- | --- |
| `stockKeyword` | 名称/编码关键字 |
| `stockStatus` | LOW / OUT / HEALTHY；停用范围不采用可用库存状态筛选 |
| `stockPage` | 当前清单页，与记录/报表的 `page` 分开 |
| `inventoryLifecycle` | ACTIVE / ARCHIVED / ALL，继续兼容现有停用链接 |
| `materialId` | 精确原料详情及来源上下文 |

筛选编辑后点击“搜索”应用，未应用条件时禁止刷新、分页或导出旧结果。清除条件回到启用范围第一页；概览计数仍是全店启用原料，与筛选结果数分开。切页、刷新、前进/后退和关闭详情保留已应用条件；结果减少导致末页为空时收敛到有效页，不冻结跨页结果。

从详情或行内记录入口默认查询近 30 个本地自然日，包含原料 ID。原有记录/报表页继续允许修改区间、类型等条件，保留起始含、结束不含口径和完整报表快照。其收支/分析/流水导航保留独立清单上下文，“返回原料”会重新打开来源详情并恢复原清单条件/页码。清单 CSV 继续只导出已应用筛选的当前页，不描述为全量记录。

预警“查看库存”改为按原料 ID 直接打开详情，替代按编码包含搜索；相似编码或目标不在当前清单筛选中，也不会跳到另一原料。浏览器后退可重新读取来源预警。

## 门店与实现边界

本轮仅修改 Web，复用既有门店原料详情、台账写入、关联查询、预警和采购/盘点 API；无新增接口、迁移或库存写规则。详情仍由服务端按签名商家门店与复合原料键隔离，不从 URL 增加门店权限。链接依赖当前已授权选店，不自动切店。切店清理原料详情 ID；重复、超长或带控制字符的 ID 不用于打开详情。

跨记录/报表携带的上下文仅取原料清单字段及来源 ID，不传播查询中的 storeId/tenantId。原料详情与清单都忽略已失效请求；详情还核对返回的门店/原料身份。状态变化、订单预占、并发库存和停用依赖继续由现有服务端事务保护，客户端展示不构成库存承诺。

未提交调整/停用原因只存在当前窗口；关闭、离开或刷新页面不会保存到 URL 或本地存储。历史名称、备注和单位保持业务原文，界面/数量/日期支持中英文。员工动作权限、成本估值、调拨和跨店合并报表仍未由本轮实现。
