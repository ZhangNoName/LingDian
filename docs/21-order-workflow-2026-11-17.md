# 商家订单多语言、筛选链接与交互 Review · 2026-11-17

## 产品流程

将仍使用中文宽表和固定宽度弹窗的商家订单页整理为“查询 → 查看详情 → 跟进履约/确认敏感操作 → 返回列表”的单一路径。

- 页面、指标、筛选、状态/渠道/来源、详情、时间线、确认提示和错误提供简体中文/英文；日期、数量与 CNY 金额按语言格式化。商品名、顾客填写内容、操作备注和既有审计文本保持原文。
- 桌面列表保留订单/取餐码、顾客、餐品摘要、状态、应付金额和时间；来源、渠道、完整餐品/选项、配送地址和时间线集中在详情。手机使用订单卡片，首屏优先展示订单总数/待付款/已付，退款及金额汇总可展开查看，避免指标占满首屏或让用户横向寻找操作列。
- 详情使用与库存一致的共享 Dialog，手机限制可视高度并内部滚动，长订单号、地址、备注可换行；保留取餐营业日、原料预留截止和历史空字段占位。
- 备餐、待取餐和完成等常规履约动作直接执行。现金收款、现金退款相关状态、取消/超时/失败及删除先显示订单状态和具体后果，再确认执行；取消确认不发请求。
- 现金收款提示确认实际收款并扣减原料，现金退款提示核实退现且原料不自动回补。线上及未知历史支付渠道继续禁止手工收款/退款，服务端仍是最终权限和状态依据。
- 保存期间所有操作、备注和关闭按钮禁用，防止重复提交；浏览器检查补齐了右上关闭按钮的禁用显示。成功提示在弹窗内可见并可被辅助技术读取，失败保留说明且提供刷新详情入口。
- 删除是软删除，只在既有允许状态开放；不会因为 UI 精简扩大交易权限。状态已经变化或遇到活动支付时，由既有后端检查拒绝，前端不强行改写。

## 可分享筛选

URL 保存已查询的 `keyword`、`status`、`orderType`、`paymentChannel`、`startAt`、`endAt`、`page`、`pageSize` 和详情 `orderId`。输入草稿与操作说明不写入链接。

- 默认全部日期；选择日期时两个边界必须完整有效，结束日包含当天，转为下一本地日零点排他边界。最大 366 天，显示浏览器时区及精确下单时间范围。共享的精确时刻在只改状态/关键词等非日期条件时保持不变，避免不同时区的查看者意外把时段扩为本地整天。
- 查询、重置、页码、每页条数和详情打开/关闭通过路由表达，刷新、返回及复制链接可恢复。翻页回到结果区开头；删除/并发更新导致当前页超出总页数时自动回到最后有效页。无效枚举、非法/反向日期、越界页码和无关参数归一化；缺省页码/条数不冗余写入 URL。
- 草稿未查询时明确提示，禁用翻页与刷新，避免把旧条件的结果误当成新结果。加载失败明确展示错误，指标不冒充旧查询的新数据。
- 复制链接是用户主动操作，包含搜索条件；访问者仍需要相应门店授权。URL 不携带门店 claims、token 或授予权限的参数。
- 商家切店时先清除旧 `orderId`，保留列表筛选，再切换上下文。页面卸载和请求序列使旧详情/列表响应失效；已发出的状态变更仍由服务端按请求时门店验证，返回后不发起使用新门店的旧对象查询。

列表和汇总仍是独立接口，可能在并发写入时处于相邻时点；两者使用同一已查询条件，不把它们描述为同一个原子快照。汇总接口内部在一个 RepeatableRead 事务中按状态分组。

## 汇总与日期修复

Review 发现旧汇总在 `scopedWhere` 之后覆盖 `status`，导致选择 PAID 后，待付款/退款指标和金额仍可能统计其他状态。现在先按完整范围和筛选分组，再计算各项数值，保留门店、顾客 owner、状态、类型、渠道、日期和关键词交集。

金额口径沿用旧订单汇总：PAID/PREPARING/READY/COMPLETED/REFUNDING/REFUNDED 的应付金额，明确包含退款相关订单；它不同于经营概览的“有效成交额”，也不是现金实收或净收入。使用 Decimal 汇总到整数分后检查安全整数，超限明确失败。

新 Web 查询发送 `startDate`（含）与 `endBefore`（不含），与经营概览的期间语义对齐；旧 `endDate` 仍为包含边界，兼容既有管理端和 API。两种结束边界不能混用；反向或无效范围拒绝。查询页码、关键词和状态操作说明增加服务端长度限制，操作说明及可选操作名至多 191 字，匹配数据库列容量。

商家修改/删除请求不再发送客户端“操作人”文案；身份仍由 merchant controller 使用当前 session user ID 写入。未知未来状态的 UI 操作集合为空，不再在详情中崩溃或猜测工作流。

## 架构与验证

订单页拆为路由/加载与操作编排、筛选编码器、locale/presentation、列表、指标和详情组件，使用原生表单/表格、手机卡片与现有共享 Dialog；没有添加渲染库或改动支付/库存状态机。

- 单元测试覆盖筛选往返、非法链接修复、日期错误、详情与列表状态分离、英文标签、线上支付限制、未知状态保守处理及请求边界。
- SQLite 执行实际分组查询适配测试，验证 PAID/REFUNDING 过滤交集、门店/软删除隔离、精确金额、新排他/旧包含结束边界；DTO 覆盖日期、页码、关键词及备注限制。
- 在新的临时 MySQL 8.4.13 完整重放现有 16 个迁移并通过无漂移校验，扩展已有隔离数据库验证：生产 OrdersQueryService 的列表/汇总同条件只返回期间内 PAID，退款汇总不混入已付数，旧 endDate 保留包含语义。原有库存预占、回滚、预警和占用核验继续通过。本轮没有新增迁移或连接业务库。
- 浏览器使用双店合成 API 数据，验证筛选/日期参数、复制链接、刷新恢复、翻页、线上支付动作限制、现金确认与保存锁、备注传递、删除确认/取消、英文、390px 卡片和详情、操作失败及切店清理。UI 验证不等同于真实支付厂商端到端验收。
- `pnpm test`：684 项通过，1 项因缺少 Docker Compose v2 跳过；`pnpm run type-check`、`pnpm run build`、文档链接检查及 `git diff --check` 通过。构建保留既有上游工具链非阻断警告。最后浏览器回归确认详情返回、越界页码收敛、手机首屏订单卡片和共享精确边界不被非日期筛选改写。临时 MySQL 与 Web 验证进程在验收后停止并清理临时数据库运行目录。
