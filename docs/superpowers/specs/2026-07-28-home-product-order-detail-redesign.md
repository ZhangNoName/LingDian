# 首页、套餐选择与订单详情重设计

## 背景与目标

当前首页把会员信息置于首屏最上方，品牌和商品氛围较弱；商品规格页能完成选择，但不适合展示套餐中“固定包含 + 可替换”的结构；订单详情能展示信息，但取餐状态和关键操作不够突出。

本次重设计参考用户提供的华莱士套餐选择截图，目标是：

- 首页先建立餐饮品牌与活动氛围，再承接会员和点餐入口。
- 菜单页点击“选规格”后进入独立的套餐选择页，在一个页面完成套餐理解、规格选择和加入购物车。
- 订单详情首先回答“订单现在怎样、去哪里、如何取餐”，再展示商品、金额和订单档案。
- 延续项目现有红色品牌主色和 uni-app 技术体系，不照搬第三方商标、文案或包装。

## 设计原则

1. **首屏先商品后个人。** 首页顶部使用真实餐品/品牌活动图，会员信息下移为叠压卡片。
2. **黄金分割组织视线。** 首页活动图宽高约为 `1.618:1`，主视觉焦点放在横向约 61.8% 的位置；会员卡叠压图片下沿，形成从品牌到个人权益的自然过渡。
3. **选择即反馈。** 套餐选项的选中状态、加价、已选摘要、总价和优惠同步更新。
4. **状态优先。** 订单详情把取餐号、状态进度和门店放在金额与订单编号之前。
5. **兼容真实接口。** 新字段为可选增强；接口数据不完整时使用已有商品、规格和图片组成可用视图，不制造空白页面。

## 首页设计

### 页面结构

从上到下排列：

1. 自定义导航栏。
2. 品牌活动主图 `HomePromoHero`，内容区宽度约 `702rpx`、高度约 `434rpx`，圆角 `24rpx`。
3. 会员信息 `MemberStrip` 下移，并向上叠压主图底部约 `36rpx`；其视觉权重低于活动主图。
4. 堂食/外卖服务方式卡片。
5. 推荐商品区。

主图必须使用真实位图资源，不使用 CSS 图形或文字假装图片。若活动资源尚未配置，使用本项目生成的无品牌餐品横幅作为默认图；加载失败时显示静态图片占位状态。

### 行为

- 点击活动主图进入点餐页。
- 点击会员卡未登录态进入登录页，已登录态保持当前权益展示。
- 服务方式和推荐商品的既有跳转保持不变。

## 套餐选择页设计

### 进入方式

菜单商品的“选规格”按钮跳转到 `/pages/spec/spec?id=<productId>`。该页面是独立的套餐选择页，不使用底部弹层。

### 页面结构

1. 顶部导航标题为“套餐”，保留返回能力。
2. 大幅商品主图，白底、完整展示主体，图片区域约占首屏宽度的 56% 高度。
3. 商品标题、简短说明、分享入口；分享入口仅在平台能力允许时出现。
4. “已包含”区域：
   - 固定包含项以两列商品卡展示图片、名称和数量。
   - 可替换项使用同样的两列卡片，选中态为品牌红描边和选中标记。
   - 有加价的选项显示 `+¥x.xx`，切换后立即更新总价。
5. 多个规格组按组名依次排列；每组明确“任选 1”“必选”等约束。
6. 吸底结算区分为三层：优惠提示、已选缩略图摘要、价格与主按钮。底部安全区必须适配微信小程序。

### 交互与计算

- 每个单选规格组始终只有一个选中项，首次加载默认选择第一项。
- 选项切换后，缩略图摘要、规格文本和价格增量同步更新。
- 最终金额为 `商品基础价 + 所选规格加价`，再乘购买数量。
- 优惠金额为原价与最终金额的非负差值；无优惠时隐藏优惠提示。
- 数量最小为 1。
- “加入购物车”成功后提示成功并返回点餐页；“立即购买”进入提交订单页。
- 商品或接口加载失败时展示明确空态，并允许返回菜单，不显示半成品底栏。

### 数据模型

在现有 `ProductDetail` 上新增可选套餐展示字段：

- `includedItems?: ProductIncludedItem[]`：固定包含的餐品及数量。
- 继续使用 `optionGroups` 表示可替换选择；`ProductOption.priceDelta` 表示加价。

`ProductIncludedItem` 包含 `id`、`name`、`imageUrl`、`quantity`。当接口没有 `includedItems` 时，展示当前商品主项，并从 `comboImages` 补充只读缩略内容；不改变后端接口的必填契约。

## 订单详情设计

### 页面结构

1. 状态主卡：状态标题、说明文案、取餐号；待取餐/制作中时取餐号使用最大字号。
2. 订单进度：下单、支付、制作、待取、完成五个节点；取消与退款状态改为对应说明，不伪造正常进度。
3. 门店卡：门店名称、地址、服务方式和期望时间。
4. 商品卡：商品图片、名称、规格、数量和价格。
5. 金额卡：商品金额、优惠项、实付金额和积分。
6. 订单信息卡：订单编号、下单时间、支付方式、备注等，保留复制能力。
7. 吸底操作：已完成订单显示“再来一单”；待支付订单预留“取消订单 / 去支付”；其他状态只显示当前安全可用操作。

### 状态映射

- `pendingPay`：待支付，突出剩余支付动作。
- `paid` / `making`：已支付或制作中，显示正常进度。
- `ready`：待取餐，突出取餐号。
- `finished`：已完成，提供再来一单。
- `cancelled`：已取消，不显示取餐进度和购买底栏。
- `refunding` / `refunded`：显示退款说明，不复用制作进度。

## 组件边界

- `HomePromoHero.vue`：只负责首页活动图、失败占位和点击事件。
- `ProductBundleGrid.vue`：只负责固定包含项展示。
- `ProductOptionGrid.vue`：负责单个规格组和选中事件，不计算订单总价。
- `SpecSelectionDock.vue`：展示已选摘要、优惠、数量和主操作。
- `OrderStatusHero.vue`：负责订单状态、取餐号和进度映射。
- `OrderStoreCard.vue`：负责门店与履约信息。

页面负责加载数据、维护选择状态、计算价格并组合组件；服务层负责把接口数据映射为页面可用模型。

## 错误与边界处理

- 图片加载失败显示静态餐品占位，不使用持续动画。
- 名称最多显示两行，超长连续字符允许断行，不能撑破卡片。
- 无规格商品仍可直接加入购物车，页面展示“默认规格”。
- 未找到商品或订单时展示空态与返回入口。
- 订单详情沿用客户登录校验；未授权时不提前请求订单数据。
- 固定底栏为内容预留等高底部空间，避免遮挡最后一组商品。

## 测试与验收

### 自动化测试

- 首页主图在会员信息之前，且存在黄金比例尺寸约束。
- 菜单“选规格”跳转携带正确商品 ID。
- 默认选中每组第一项，切换选项后选中摘要和加价计算正确。
- 数量变化正确影响最终金额，数量不能小于 1。
- 缺少 `includedItems` 时兼容映射仍返回可展示内容。
- 订单状态到标题、进度和主操作的映射正确。
- 长文本和图片失败状态具备稳定样式。

### 构建与视觉验收

- `pnpm type-check` 通过。
- Vitest 全量测试通过。
- H5 与 `mp-weixin` 构建通过。
- 在 390×844 移动视口检查首页、套餐选择和订单详情。
- 在微信开发者工具重新编译，检查控制台无应用错误或警告。
- 商品详情与参考截图进行同视口对照：重点检查主图占比、两列选择卡、吸底摘要、间距、圆角、字体层级和安全区；修复 P0/P1/P2 视觉差异后才交付。

## 非目标

- 不复制华莱士名称、商标、包装或促销文案。
- 不新增支付、分享、退款等后端能力。
- 不改造管理端商品配置流程。
- 不在本次范围内重做菜单页、购物车或登录页的整体视觉。
