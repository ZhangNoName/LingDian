# 小程序移动端界面精修设计

## 背景与目标

本次优化以真实微信小程序截图为视觉依据，覆盖首页、点单页、登录页和四项底部主导航。保留现有接口、路由、认证、购物车和点单业务逻辑，只调整界面结构、视觉比例、交互反馈和移动端安全区适配。

成功标准：

- 首页首屏具备明确的品牌视觉入口，不再由会员条直接占据顶部。
- 登录表单在常见手机高度内处于视觉中部，键盘弹起后仍可滚动和操作。
- 点单页的内容区、空状态、分类侧栏和购物车栏不互相遮挡。
- 底部导航图标清晰可辨，点击区域满足移动端操作需要。
- 三个页面使用同一套红色品牌色、圆角、阴影、字号和间距规则。

## 设计方向

采用“统一精修”方向：延续现有红、白、暖金配色和卡片式结构，不重新设计业务流程，也不扩大页面范围。相较于大幅增加首页海报高度，该方向优先保证堂食、外卖等主要入口仍能在首屏快速触达；相较于极简功能化方向，它保留足够的品牌识别和餐饮氛围。

## 页面设计

### 首页

页面从上到下为：品牌占位图、会员条、服务模式卡片、推荐区域、底部主导航。

- 品牌占位图位于首页内容最上方，建议高度约 `240rpx`，宽度铺满内容区，圆角约 `24rpx`。使用真实图片资源，不使用 CSS 绘制的假图片。图片需要支持 `aspectFill`，并提供加载失败后的中性背景降级。
- 会员条移至占位图下方，压缩高度与左右信息宽度，避免登录按钮、积分和优惠券在小屏上重叠。
- 堂食与外卖卡片维持双列，增加图标直径和卡片内部留白；标题、说明和图标形成稳定的三层层级。
- 推荐区保留有数据和无数据两种状态。空状态减少无意义留白，主按钮与说明保持在同一卡片内；有数据时维持双列商品卡片。
- 页面整体允许纵向滚动，底部内容增加与主导航相匹配的安全间距。

### 点单页

页面从上到下为：自定义导航、门店信息、左右菜单区、悬浮购物车栏、底部主导航。

- 自定义导航和门店信息压缩为清晰的两层顶部区域，并保留微信小程序系统胶囊的安全空间。
- 左侧分类栏宽度保持约 `156rpx`；选中项使用红色短条、白色背景和更高字重。
- 右侧商品区正常加载时展示商品列表；无商品时显示完整空状态，包括简洁图标、主文案和辅助说明，并在可用内容区域中居中。
- 购物车栏改为左右留白的悬浮圆角容器，固定在底部主导航上方。金额、优惠信息和结算按钮必须完整显示，不能被屏幕边缘或主导航裁切。
- 空购物车使用深灰底和弱化按钮；存在商品时恢复品牌红和可点击结算状态。

### 登录页

登录页使用纵向滚动容器和居中内容壳层。

- 标题、说明、表单卡片和第三方登录组成一个内容组，在常见手机高度下位于视觉中部略偏上位置。
- 顶部预留系统状态栏和微信胶囊安全空间；底部预留键盘与 Home Indicator 空间。
- 手机号、验证码和按钮维持现有认证逻辑，增加统一的聚焦态、禁用态、发送中状态和倒计时反馈。
- 主按钮使用品牌红；验证码按钮使用浅红背景，避免当前浅绿色与品牌体系冲突。
- 第三方登录入口弱化为次级操作，但保持足够的点击尺寸。

### 底部主导航

- 继续使用 `首页 / 点单 / 订单 / 我的` 四项结构和现有路由。
- 图标视觉尺寸由约 `30rpx` 提升到约 `42rpx`，点击区域不小于 `88rpx × 76rpx`。
- 图标与文字的间距调整为约 `8rpx`；选中项使用品牌红和较高字重，未选中项使用中性灰。
- 导航容器正确叠加 `env(safe-area-inset-bottom)`，不额外绘制系统 Home Indicator。
- 图标继续来自项目图标包；若现有字形在放大后不一致，只在图标包内统一替换，不在页面中手写图形。

## 组件与代码边界

本次修改集中在现有组件中，不新增路由或业务状态：

- `pages/home/home.vue`：调整首页模块顺序、滚动和底部间距。
- `components/home/*`：新增或扩展品牌占位图组件，精修会员条、服务卡片和推荐区。
- `pages/order/order.vue` 与 `components/menu/*`：优化菜单布局、空状态和购物车栏。
- `pages/auth/login.vue`：重排登录内容壳层并补齐表单视觉状态。
- `components/app/AppTabBar.vue`：放大图标和触控区，统一选中态。
- `theme/miniapp-tokens.*`：仅补充能够被多个页面复用的尺寸或视觉 token，避免页面内散落同类常量。

现有服务层、类型、认证导航、购物车汇总和菜单请求保持不变。展示组件继续通过 props 接收数据并通过事件向页面上抛操作。

## 状态与错误处理

- 首页品牌图加载失败时显示与页面一致的中性色背景和品牌标识，页面布局不得塌陷。
- 菜单加载中保留稳定内容高度；请求失败继续使用现有 Toast，同时右侧内容区显示可理解的错误提示和重试入口。
- 菜单成功但没有商品时显示空状态，不与“请求失败”共用文案。
- 登录发送验证码和提交期间禁用重复操作；现有错误文案映射继续生效。
- 所有固定底栏在有、无安全区的设备上都不得覆盖可操作内容。

## 可访问性与交互

- Tab、服务模式卡片、登录按钮、验证码按钮、购物车按钮保留键盘和点击操作。
- 交互控件提供明确的 `aria-label` 或可读文本。
- 红色文字与浅色背景、白色文字与品牌红背景保持可辨识对比度。
- 禁用态不能只依赖透明度表达，同时调整背景或文字颜色。

## 验证计划

- 运行 uni-app 类型检查与现有 Vitest 测试。
- 构建 H5 版本，确认没有模板、样式或资源路径错误。
- 在接近真实截图的竖屏视口中检查首页、点单空状态和登录页。
- 重点核验顶部系统安全区、底部导航、购物车栏、登录表单居中以及小屏滚动。
- 将真实截图与本地实现截图进行同视口对照，修复影响布局和可用性的高、中优先级差异。

## 不在本次范围

- 不修改后端接口、认证协议、购物车计算或订单流程。
- 不新增门店选择、搜索、活动、优惠券等业务页面。
- 不改动微信小程序系统状态栏、胶囊按钮或 Home Indicator。
- 不引入新的全局状态库或 UI 框架。
