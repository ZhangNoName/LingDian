# Uni-app 预览与 UI 修复设计

## 目标

修复微信开发者工具预览超时的已知环境差异，并提高点单页面在异常长文本和缺失商品图片场景下的可用性。修复不得篡改后端商品数据，也不得改变既有下单流程。

## 方案

1. 在 `uniapp/src/manifest.json` 的微信小程序配置中固定基础库版本 `3.15.2`，使重新构建的 `project.config.json` 与本机可正常运行的微信示例项目保持一致。
2. 分类侧栏名称最多显示两行，使用断词和溢出隐藏保护固定宽度；商品标题同样最多两行，并允许连续英文或异常字符安全换行。
3. 商品图片继续优先使用接口地址。地址为空时，依据商品所属分类稳定选择本地 burger、snack、drink、combo 占位资源；图片加载失败时，首页和点单页均显示带餐品图标与“图片待更新”文案的静态占位，不使用持续闪烁的骨架屏。
4. 后端返回的异常商品名称按原值展示，通过布局约束防止破坏页面；数据清理仍由后端或数据管理流程负责。

## 数据流与边界

- `catalog.ts` 负责将接口商品映射成视图模型并选择稳定的本地兜底图片。
- 首页推荐卡与点单商品项各自处理图片加载失败状态，只影响图片区域。
- 分类名和商品名的防溢出只由组件样式控制，不截断视图模型数据。
- 微信基础库配置只影响生成的小程序工程，不影响 H5。

## 验证

- 先添加失败测试，覆盖基础库版本、分类两行省略、商品名安全换行、分类化兜底图片和失败占位。
- 运行 uni-app 单测与类型检查。
- 分别构建 H5 与微信小程序。
- 在 390×844 手机视口检查首页、点单页；在微信开发者工具重新编译并查看控制台和模拟器。

## 非目标

- 不删除或改写数据库中的异常商品记录。
- 不重做现有视觉体系、导航或购物流程。
- 不引入新的图片依赖或网络图片服务。
