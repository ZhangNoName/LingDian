# 小程序全页布局优化设计

## 目标

将 uni-app 微信小程序的首页、点单、商品详情、结算、订单、订单详情和我的页面收敛为一套一致的移动端界面。改造只调整表现层与交互布局，不改变现有接口、数据模型和页面路由。

## 设计原则

- 优先保证手机首屏的信息层级、可点击区域和底部安全区。
- 使用统一的页面背景、间距、圆角、卡片边框和文字层级，避免每页独立定义视觉规则。
- 页面导航避开微信右上角胶囊；底部操作和 TabBar 留出安全区，不遮挡滚动内容。
- 商品与订单缩略图使用稳定的宽高比例和加载/空图状态，图片失败不能撑高或压缩卡片。
- 所有图标优先复用 `@lingdian/icons` 的 Lucide 图标。小程序端使用静态组件标签，不使用动态 `component :is`。
- 小程序组件样式只保留 class 选择器，移除标签、ID、属性选择器及其间接产物。

## 公共结构

### 视觉令牌

在小程序主题变量中统一页面边距、卡片内距、间距、圆角、文字等级、边框和阴影。页面只消费令牌，不在各组件中重复散落常量。

### 顶部与底部

`AppNavBar` 负责安全区、页面标题、返回和操作图标。`AppTabBar` 固定在底部并为内容区提供等高的底部避让。页面使用标准滚动内容区，不通过硬编码视口高度制造空白区域。

### 图标

在 `packages/icons/src/miniapp.ts` 集中导出小程序需要的 Lucide 图标别名。每个页面组件按需静态导入，图标按钮具备明确的可点击尺寸和无障碍文本语义。

## 页面改造

### 首页

- 会员区压缩为一条信息带，姓名、积分和优惠券对齐且不与胶囊区域冲突。
- 堂食与外卖入口使用等高双列操作卡，图标、主标题和辅助说明垂直对齐。
- 推荐区采用稳定双列商品栅格：固定图片比例、两行内商品名、价格和加购按钮落在卡片底部。

### 点单与商品详情

- 点单页将门店信息、分类栏、商品区和购物车结算栏组织为可独立滚动的区域。
- 分类栏显示当前选择状态；商品行明确图片区、标题/规格、价格与加购控件。
- 商品详情的图片、规格组选项、数量和主操作采用一致的间距和底部固定操作区。

### 结算

- 门店、取餐方式、商品清单和金额拆分为可扫描的连续分区，不使用嵌套卡片。
- 支付按钮固定在底部安全区上方，金额、优惠与应付金额保持可见。

### 订单与详情

- 订单页的页签位于标准导航下方；订单列表设置统一页面内距和卡片间距。
- 每张订单卡按“门店和状态、时间和商品缩略、金额和操作”排列，时间用本地可读格式展示。
- 订单详情保持相同的信息顺序，并让状态、金额与关键操作优先可见。

### 我的

- 个人信息、权益、管理入口按功能区组织，入口使用 Lucide 图标并统一图标容器尺寸。
- 管理入口栅格保持固定列数和点击区域，文字溢出不改变布局。

## 实施边界

- 不修改 API、缓存、订单状态规则、购物车计算和路由参数。
- 不引入新的图标库、UI 框架或运行时依赖。
- 保留已有页面和组件职责；仅在多页重复样式确实需要统一时抽取公共组件或主题变量。

## 验收标准

- 微信小程序开发模式和构建模式均可成功编译。
- 首页、点单、商品详情、结算、订单、订单详情、我的均无内容被顶部胶囊、底部 TabBar 或安全区遮挡。
- 所有图片区域在加载失败、空数据和多行文本时保持稳定布局。
- 小程序构建输出不再出现组件 WXSS 选择器不支持告警。
- 不含动态 `component :is`；图标均来自集中导出的 Lucide 小程序图标入口。
