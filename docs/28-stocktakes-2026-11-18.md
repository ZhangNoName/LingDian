# 盘点单与库存过账 · 2026-11-18

## 操作流程

库存页增加独立“盘点单”入口，保留原有单原料即时调整。商家选择当前门店的 1–50 种原料、填写盘点名称和说明后创建草稿；查找、翻页不会清除已选原料。每种原料保存名称/编码/单位、物理账面、订单占用、库存版本和读取时间快照。

实盘填写现场物理数量，包含已预占但未消耗的原料；空白表示尚未盘点，零是有效的零库存结果。可分次保存，关闭/重载后继续填写。草稿不写库存、不产生库存流水。界面分别预览每种原料的盘盈/盘亏，不合计不同单位。未保存数量阻止过账/导出/重新读取，关闭时提供继续填写或明确放弃。

全部实盘保存后单独“确认过账”，先显示影响，再确认执行。过账成功后只读，库存变动记录可反查盘点单，现有区间报表自动计入 COUNT 盘盈/盘亏。盘点单支持状态/名称筛选、URL 详情及已保存记录 CSV（门店、说明、账面读取时间、数量/占用、实盘/差异、创建与过账元数据），沿用公式注入转义；CSV 导出当前整张单据而非列表分页。

盘点不冻结收货、订单或库存。如果任一原料版本变化，整单拒绝过账。读取最新记录后可选择“重新取账面并重盘”，确认后更新全部快照并清空全部已保存实盘，要求现场重新盘点，不自动套用旧差额。实盘低于当前订单占用量时也拒绝；原料短缺应先处理订单/现场原料，不能通过盘点强制释放订单占用。

草稿可确认取消，保留记录且不调整库存；已过账单据不能取消、修改或撤销，纠错另建单据。当前复用商家身份和门店 scope，不宣称提供员工审批、职责分离、定时盘点、扫描枪、批次/库位、盲盘或成本估值。

交互参考 [Shopify stock counts](https://help.shopify.com/en/manual/inventory-and-locations/inventory-counts) 的建单、记录、复核后调整及历史追踪，以及 [Zoho stock counting](https://www.zoho.com/inventory/help/items/stock-counting.html) 的独立盘点记录。这里实现的是当前商家的过账确认；多人审批权限仍属于独立缺口。沿用现有 Dialog、原生表单、原料卡片和全局中英文，手机口径说明可展开。

## 一致性和隔离

- 创建键按门店唯一，SHA-256 指纹包含 actor、名称、说明及排序后的原料 ID；同内容并发/重试只建一单，修改内容复用键拒绝。范围检查发生在任何请求重放/业务查询之前。
- 草稿保存、重新取账面、过账和取消使用单据版本条件更新认领草稿，再读取锁定后的记录。保存必须完整匹配该单原料行；不能注入其他行、重复行或漏行。旧版本/已结束单据拒绝修改，失败不消耗版本。
- 过账按原料 ID 顺序逐行核对快照版本，以库存 CAS 更新物理量/可用量，保留占用量和阈值。每行（包括无差异）生成有来源关联的 COUNT 流水，快照与说明仍保留在单据中。单据状态、全部原料、流水、预警和身份审计同事务提交，任一失败全部回滚。
- 已过账/已取消的终态重试返回原记录，不重复库存写入或审计；并发首次过账最多一笔成功写入，竞争请求可能收到版本/状态冲突，重新读取即可确认最终结果。
- 表与行保留当前门店过滤，原料行、盘点单、原料和来源流水有门店复合外键；同时管理两家门店的账号也不能用 A 店路径读取或修改 B 店单据。切店清除 stocktakeId，页面销毁后旧请求失效。
- 详情/列表在 RepeatableRead 中读取记录与当前库存；当前值只用于草稿变化提示，结束单据的结果使用保存快照。业务写入使用 ReadCommitted 和版本条件控制，长批次过账事务超时 30 秒。
