# 原料停用、恢复与历史保留 · 2026-11-18

## 操作流程

库存清单增加启用/停用/全部状态筛选。启用原料可“停用”，停用原料可“恢复启用”；均先展示影响、当前账面和订单占用，填写原因后确认。状态版本变化或结果不明时，可保持原因不变重试，或“读取最新记录”核对；读取不会自动重做操作，原因保留。若最新记录已是目标状态，提示完成并核对列表。

停用必须满足：账面量、可用量和占用均为零，没有有效预占记录，没有任何销售配方引用（包括停用规格），没有该原料仍未收齐的有效采购，没有包含此原料的盘点草稿。分别给出库存/占用、配方、采购、盘点阻止原因；运营人员先处理关联业务，再停用。已有库存不能靠停用隐藏，也不能强制释放待付款订单的占用。

停用不是删除。原料 ID、编码和固定单位保留，编码不能重新分配给其他原料；库存流水、收支/损耗分析、采购与收货、已结束盘点和预警历史继续可查。库存历史/报表返回清单时保留原料状态筛选。默认原料查找、配方、采购、盘点及补货建议仅使用启用原料；旧表单也会被服务端复查。恢复不增加库存，之后可重新采购、配置配方、盘点和调整。

交互参考 [Zoho Inventory 原料/商品的停用与历史保留](https://www.zoho.com/us/inventory/help/items/item-managing.html)；本系统采用适合现有配方/占用模型的更严格前置条件，不提供批量删除、库存清零、业务单据撤销或自动改配方。

## 预警、概览与导出

库存三项计数和经营工作台的低库存/缺货计数只统计启用原料，停用数单独用于筛选入口。停用行使用中性色，保留历史查看和恢复入口，隐藏调整/补货按钮；“补至阈值”在界面显示“—”、CSV 留空，不把停用原料描述为需要补货。CSV 包含当前页、原料状态范围及每行状态，沿用公式注入防护。

停用会在同一事务解除该原料的当前预警，明确记录 `ARCHIVED`；库存恢复或阈值条件恢复则记录 `RECOVERED`。详情及 CSV 展示解除原因，不将停用描述为补货成功。预警的“查看库存”按原料当前启用状态定位对应清单，历史停用预警在恢复后也能进入启用清单。恢复时按现有库存重新评估，零库存会建立新的缺货预警，不复活已结束的旧记录。

界面沿用现有表格、Dialog 和原生表单，中英文共用语言设置；手机弹窗可滚动、文本可换行。保存/重新读取时禁用重复操作和关闭，错误保留原因；状态筛选可通过 URL 重载。没有新图表库、动画、虚构汇总或装饰性指标。

## 一致性与范围

所有读取/写入先核对签名商家门店 scope，再按门店复合键访问原料。生命周期修改在 ReadCommitted 事务中用参数化 `SELECT … FOR UPDATE` 锁原料、校验版本和全部依赖，再递增版本、保存状态/原因/经办人/时刻，更新预警并写业务审计。任一步失败全部回滚，不生成虚假的出入库或盘点流水。

直接重复相同用户、目标状态、原因和原版本的最后一次操作，可以返回同一结果；只有该结果版本仍是当前版本时才接受。之后的恢复/再停用、库存修改或其他用户/原因不会被旧请求跨版本重放。没有无条件覆盖或强制停用入口。

采购建单、配方保存和盘点建单按同一原料顺序加锁，并在锁内验证启用状态，防止检查依赖后另一个请求又新增引用。创建盘点使用 ReadCommitted，在全部原料锁定后读取账面快照。手工调整、收货、盘点过账及新订单预占也检查启用状态；已有订单扣料/释放保留原结算路径，不能借状态变化破坏历史预占。锁定读取不修改原料更新时间；已提交创建请求的重放继续返回原单据，不新建引用。

此功能仍沿用现有商家身份与门店授权，不代表增加了员工动作权限、审批或职责分离。

## API 与部署

| 方法与路径（库存前缀下） | 用途 |
| --- | --- |
| `GET /?lifecycle=ACTIVE\|ARCHIVED\|ALL` | 默认启用清单；同一快照读取列表及启用/停用计数 |
| `GET /items/:itemId` | 门店内最新原料状态，用于复核 |
| `PUT /items/:itemId/lifecycle` | `isActive`、`expectedVersion`、必填 `reason`；严格布尔/版本/白名单 |

新增 `20261118_zzzz_inventory_lifecycle`：原料启用状态、最后状态版本/原因/经办人/时刻、门店状态索引及预警解除原因。旧原料默认启用，旧已解除预警标记为库存条件恢复；不改写历史数量、单据或原料编码。先通过安全迁移入口应用并重新生成 Prisma Client，再发布 API/Web；旧 Web 仍只看到默认启用清单。不要直接 db push 或改写已执行迁移。
