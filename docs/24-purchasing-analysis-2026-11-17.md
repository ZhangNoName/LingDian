# 收货分析与补货建议 · 2026-11-17

## 使用流程

采购页面增加“收货报表”和“补货建议”，与采购单、供应商共用导航。桌面使用紧凑表格，手机使用卡片和可滚动导航，表单、结果、错误和金额均提供简体中文/英文。没有增加装饰图表或新的 UI 库。

收货报表默认近 30 个本地日，可查询最多 366 天；URL 保存精确收货时间边界、关键词、供应商/原料筛选及当前子视图。结束日期包含当天，转换为下一本地日零点的排他边界；共享的精确时间在只修改关键词/对象条件时保持原样，并显示浏览器时区及精确区间。

报表提供供应商、原料汇总和收货明细，支持点击汇总筛选、清除对象筛选、打开采购单详情、刷新和浏览器返回/重载。每页显示 20 行；导出包含当前筛选全部明细，与可见页无关。未应用筛选、加载、失败和空报表时不允许导出。CSV 带门店、精确区间、筛选、快照生成时间和金额口径，沿用统一的公式注入转义。

补货建议同时显示可用量、阈值、未收采购数量/单数和建议加购量，可查看仍需采购、已被未收采购覆盖或全部原料。计算说明可以展开。每种原料/单位分别判断，不合计不同原料数量。

“按建议建单”会重新读取该原料当前快照再填入数量；普通采购单添加原料也会重新读取，不再直接使用旧库存列表的缺口。建议为零时默认数量为零，必须按实际需要手工填写正数量后才能提交。用户仍可以主动增加采购，建议不会自动发单、锁定未来采购/需求或阻止其他用户建单。

## 报表口径

- 按 PurchaseReceipt.createdAt 的 `[startAt, endAt)` 统计实际收货行，不按采购单创建时间或当前状态筛选。采购单取消剩余、供应商停用/改名，不抹去此前已经验收的收货。
- 汇总持久化的每批行 costCents，不用单价乘总数量重算。数量按整数千分汇总，金额以 BigInt 累加并检查 JSON 安全整数。多批小数舍入差异保留，不把结果描述为付款、发票金额或库存估值。
- 供应商/原料按 ID 与记录快照名称、编码（原料含单位）分组，同一供应商历史名称不同可能出现多行；总供应商数按不同 ID 计数。批次/采购单数去重，关键词/对象筛选命中的行才计入金额和数量。
- 报表读取和汇总基于同一 RepeatableRead 快照，最多 10,000 行，超限或金额/数量越过安全整数明确失败，不返回成功的部分报表。

## 补货口径与隔离

建议量 = max(0, 补货阈值 − 当前可用量 − 未收采购数量)。可用量已经扣除订单预占；未收采购只包含当前门店 OPEN/PARTIAL 采购行的采购量减已收量，取消和收齐的行不再参与。收货增加现货且减少未收数量，取消剩余减少未收采购但不冲回现货。

未收采购不是现货，建议不改变库存、订单原料可用承诺或预警状态。零阈值的缺货需要人工评估；本轮没有增加销量预测、安全库存或采购提前期模型。整体建议使用同一个 RepeatableRead 快照并限制 10,000 种原料，超限要求缩小查询。

所有新接口先验证当前 merchant/store scope。查询中的供应商、原料和收货关联都保留当前门店过滤；其他门店的对象 ID 不能扩大范围。切换门店继续清理采购详情，旧请求不会覆盖新店结果。
