# 库存预警中心与 Review · 2026-11-17

## 产品流程

在实时库存状态之上，增加可持续跟进的站内预警记录：发现短缺 → 查看数量与阈值 → 记录跟进安排 → 进入对应原料库存 → 实际入库/调整 → 自动解除并保留历史。

- 顶部门店栏提供“库存预警”入口和待跟进数量。页面可见时每分钟查询，切换业务页、回到可见状态或成功确认跟进时刷新；加载失败明确显示暂不可用，不继续展示旧数字。
- 库存新增“预警中心”，显示待跟进、跟进中、仍缺货计数，支持状态、缺货/低库存级别和原料搜索、分页、详情与当前页 CSV。
- 活动记录优先展示缺货，再按发现时间从早到晚；全部/已解除历史按发现时间从新到旧。计数覆盖当前门店，不随列表筛选变化。
- 确认跟进必须填写安排，记录操作人和时间，不改变原料数量，也不能手工把仍短缺的原料标为已解除。详情可进入已按原料编码筛选的库存列表。
- 同一原料持续短缺只保留一条活动记录；低库存升级为缺货时重新提示待跟进，保留最近一次备注。可用量高于当前阈值时自动解除；后续再次短缺产生新记录。
- 界面区分处理状态与最近预警级别，避免“已解除 · 缺货”混成当前状态。新页、详情、入口及 CSV 支持简体中文/英文；手机表单纵向布局，宽表在局部滚动，不新增装饰图表。

## 数据与授权

新增 `InventoryAlert`，数量仍用整数千分量。预警保存发现时的可用量/阈值、最新记录数量、版本、跟进人/时间/备注、解除时间及门店。发现快照不随库存变动重写，当前页 CSV 区分发现时与最新记录数量，并保留门店/筛选/导出时间。

`activeItemKey` 可空唯一键保证每个原料最多一条活动记录，解除后清空；CHECK 约束活动键、状态和解除时间的一致性，复合 `(itemId, storeId)` 外键阻止跨店关联。原料 ID 是不可变身份，因此新关系使用 RESTRICT 更新策略，兼容 MySQL 对 CHECK 涉及外键列的限制。

`syncInventoryAlert` 在原料创建、手工调整、订单预占、确认扣料与释放的原事务内调用。所有写入先持有原料锁，再读取/写入预警；预警失败会让原库存事务一起失败。付款确认通常不改变可用量，不产生重复通知。阈值降低也可能解除预警，因此界面不把所有解除都称为“补货恢复”。

跟进操作采用相同的“原料 → 预警”锁顺序，在 ReadCommitted 下重新读取当前状态与版本。旧页面不能覆盖新升级；同操作者、同备注的结果不确定重试只返回既有结果，不重复写审计。升级、解除和确认跟进写入业务审计；预警详情和 CSV 展示最近一次跟进，完整变更审计仍保留在 auth audit，尚无面向商家的完整审计查询页。

所有 API 沿用 `AccessTokenGuard + MerchantGuard`，在查询或锁定任何记录前验证 signed merchant/store scope；对象按 `(id, storeId)` 查找。列表和门店计数来自同一个 RepeatableRead 快照。切店时页面和顶部提醒按门店重新挂载，过期响应不能填回新门店。

接口以 `/merchant/stores/:storeId/inventory` 为前缀：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/alerts` | 分页、状态/级别/名称编码筛选与门店计数 |
| POST | `/alerts/:alertId/acknowledge` | 版本校验、记录跟进人与安排 |

## 迁移与验证

新增 `20261117_stock_alerts`，排序在原料余额及订单预占迁移之后。只新增预警表，按当前可用量小于等于阈值回填 LOW/OUT；正可用量高于阈值的原料不回填。回填的发现时间是迁移检测时间，不虚构历史短缺开始时间，不修改原库存数量。

真实 MySQL 验证发现并修正新迁移的同日名称排序、CHECK 与级联外键的限制；诊断失败库没有被标记成功或重复使用。修正后在新的临时 MySQL 8.4.13 空库执行完整 16 个迁移，安全入口及 fresh 校验均为 `No difference detected`。另建升级库，先重放此前 15 个迁移，再放入双店的低库存、缺货、健康及有预占合成原料，执行新迁移与 drift 校验，确认只生成对应两条门店预警、按可用量回填，且复合外键拒绝跨店关联。

扩展已有 `test:inventory:mysql` 入口，仍只接受显式传入的本机专用空测试库，验证：原料零库存创建、补货解除、再次触发新记录、并发同备注确认只写一次审计、升级重开且保留备注、旧页面拒绝、门店/状态/级别/原料筛选，以及预警创建后真实唯一键失败导致原料和预警一起回滚。此前竞争下单、重复扣减/释放与收支 SQL 继续执行。

单元测试覆盖持续短缺去重、发现快照不可变、跟进语义、升级、解除/再次触发、零阈值、授权先行、对象隔离及 DTO 输入。浏览器拦截 API 验证顶栏数量、跟进备注、无法手工解除、跳转到对应库存、CSV 公式保护、升级、旧版本保留表单、已解除筛选、中英文、390px 详情、切店清空旧数据与失败禁用导出；不代表生产联调。

`pnpm test`：661 项通过，1 项因缺少 Docker Compose v2 跳过。`pnpm run type-check`、`pnpm run build`、文档链接、迁移名称/顺序、demo 清理范围及 `git diff --check` 通过；构建保留既有上游工具链非阻断警告。浏览器最后一轮同时确认手动刷新列表会同步顶栏数量，避免两处计数长时间不一致。临时 MySQL 与 Web 验证进程在验收后停止并清理临时数据库运行目录，未改动实际环境变量、业务库或系统服务。
