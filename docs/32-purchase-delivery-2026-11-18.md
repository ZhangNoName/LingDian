# 采购到货跟进与列表恢复 · 2026-11-18

## 使用流程

采购单列表现在始终显示预计到货日期，手机卡片和当前页 CSV 同样保留此字段。到货跟进提供三种范围：全部到货安排、预计早于指定日期仍未收齐、未填预计日期仍未收齐。后两种只包含待收货或部分收货单；排除已收齐和已取消单据，继续与关键词、指定未收原料相交。

先修改条件，再“查找”；未应用条件会禁用导出、翻页、列表详情和采购内视图切换，重置可直接放弃筛选草稿。手机仍折叠筛选，但始终显示已应用的状态、到货范围、日期边界/时区和关键词，避免筛选藏在折叠区；当前页 CSV 入口在手机也可用。空列表、加载失败和非法日期都有反馈，失败不导出旧列表。

采购单与供应商的关键词和页码分别保存到 URL；采购状态、到货范围和明确截止时刻也保存。刷新、浏览器返回、打开/关闭采购详情均保留上下文，详情导航不会额外请求列表。取消或收齐后当前筛选可自动移除该单；页码超过新结果范围时替换为最后一页，不循环追加无效历史。切店仍销毁旧页面并使旧请求结果失效，按新门店读取并收敛页码；原料对象筛选继续由统一切店流程清除。

交互参考 [Shopify 采购单查看和筛选](https://help.shopify.com/en/manual/inventory-and-locations/purchase-orders/viewing-purchase-orders) 的列表筛选路径，以及 [Zoho 采购单](https://www.zoho.com/us/inventory/help/purchase-orders/purchase-order-creation.html) 对预计到货日期的记录。本产品不把预计日期当作实收，不发送催货消息或自动提醒，不新增供应商通知或库存预测。

## 日期与导出口径

早于筛选采用严格小于：`expectedAt < expectedBefore`，边界时刻本身不匹配；空日期只进入“未填日期”范围。新选日期按浏览器当前时区零点转换为带时区的明确时刻。链接可以指定更精确的时刻，单独修改关键词或页码不重置其秒/毫秒；跟进口径说明可查看完整 ISO 时刻。更改日期后重新按当地零点查询。没有门店独立时区设置，不把浏览器时区描述为门店固定时区，也不自动宣称“逾期”。

采购列表与总数在同一次 RepeatableRead 事务读取；服务端分页前应用全部筛选，不能靠当前页过滤伪造全量结果。不同页是不同次读取，不宣称跨页冻结快照。CSV 明确只导出当前已载入页，包含门店、页码/总数、导出时间、关键词、状态、到货范围、明确边界与时区、指定原料和预计到货时刻；复用既有公式注入防护。收货报表的完整快照导出保持独立。

## API 与索引

既有 `GET /merchant/stores/:storeId/inventory/purchases` 增加可选参数：

| 参数 | 规则 |
| --- | --- |
| `delivery` | `ALL`（默认兼容旧请求）、`BEFORE`、`UNDATED` |
| `expectedBefore` | 仅 `BEFORE` 使用且必填；严格 ISO、必须带时区 |

缺失必需边界、向其他范围传边界、非法日期、数组或未知枚举都会拒绝。服务先验证签名门店 scope，再构建过滤；新增 active/date 条件放入 AND，保留调用方状态、关键词和原料范围，不覆盖其他过滤。即使 API 显式请求已收齐状态与 BEFORE 的交集，也不会返回已收齐单据。界面在跟进范围中固定待收货状态。

新增 `20261118_zzz_purchase_delivery`，仅增加 `purchase_orders(storeId,status,expectedAt)` 索引，无旧数据改写或新业务表。通过安全迁移入口部署后重新生成 Prisma Client，再发布 API 与 Web；旧 Web/默认查询继续兼容。不要先发布发送新参数的 Web 到不支持该参数的旧 API。
