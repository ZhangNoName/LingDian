# 原料关联业务追查 · 2026-11-18

## 操作流程

原料停用/恢复窗口增加“查看关联业务”，按配方引用、未收采购、盘点草稿分别查看。配方包含停用规格与未在售商品，并显示每份用量；采购只显示该原料尚未收齐的有效单据，并显示该原料待收量；盘点只显示草稿，实盘空白与零分别呈现。每类独立计数、每页最多 20 条，超出末页时收敛到最后一页，不静默截断。

“打开处理”复用已有配方、采购、盘点详情，一次只显示一个窗口。返回后保留原来的停用原因、关联类型和页码，重新读取原料与关联信息。清除配方引用、收齐或取消采购剩余、处理或取消盘点草稿后，再由用户确认停用；不会自动停用、改变配方或取消业务。原料账面量/占用及全部依赖仍由停用事务重新检查，不因列表展示为空就跳过校验。

配方编辑抽为共享窗口：原销售配方列表继续用同一编辑器，关联入口按 SKU 精确读取，无需在商品分页中搜索。错误保留输入、旧版本不覆盖；有未保存修改时关闭需明确放弃，保存期间禁用关闭/Esc/外部点击。原料与关联业务仍在当前门店上下文中操作，不另开丢失选店状态的标签页，不新增一级菜单。

关联面板保留刷新、空/失败状态；失败或读取中不提供旧内容导出。界面/状态/数量和日期支持中英文，手机弹窗限制高度、内容换行，展开关联时将操作说明与口径折叠，优先展示业务记录；原料名称、单号及备注仍为业务原文。关联窗口是当前操作过程中的查看状态，关闭整个原料窗口或刷新页面不会保留未提交的停用原因；不会把原因写入 URL 或浏览器存储。

## 数量与导出

配方“每份用量”、采购“该原料待收”、盘点“已存实盘”分别展示，不合计为库存消耗或总需求。未收采购不计入现货，盘点草稿不调整库存；关联快照不冻结后续业务。

导出明确为当前关联类型的当前页，包含门店、原料 ID/编码/单位、读取时间、关联类型、页码/总数、记录 ID/名称/状态、该类型数量和适用的预计到货/创建时刻。保留无法打开的配方关联计数提示，沿用 CSV 公式注入防护；不把分页导出描述为全量记录或跨页冻结快照。

## API 与多租户

库存前缀 `/merchant/stores/:storeId/inventory` 下新增：

| 接口 | 用途 |
| --- | --- |
| `GET /items/:itemId/usage?view=RECIPES&page=1` | 三类完整计数和当前类型/页的记录；view 可选 RECIPES、PURCHASES、STOCKTAKES，页大小固定 20 |
| `GET /recipes/:skuId` | 精确规格配方，含版本和完整店内原料明细 |

服务先检查签名门店范围，再查该店原料或规格。关联计数和分页在同一 RepeatableRead 事务中读取；精确配方也使用 RepeatableRead，使配方版本与明细一致。接口仅查询，不更新原料版本、库存或更新时间；已有保存/收货/盘点及停用写入继续使用原有版本、幂等和事务规则。

旧库存配方只对 SKU ID 建外键，历史错店关联仍可能存在。关联查询同时限制配方行、原料和 SKU 商品门店；不暴露其他门店的商品名、规格名、原料名或目标 ID。对于引用当前原料但 SKU 不在当前店的记录，只返回无法打开的计数，提示管理员核对，不提供跳转。现有配方列表、精确详情及保存后返回值也在关系查询中按门店过滤，保留防御性展示过滤。

不提供跨店修复、删除遗留引用或强制停用入口。此功能仍沿用商家门店授权，不代表员工动作权限或审批。
